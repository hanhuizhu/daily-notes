# Code Quality Review - 自动修复流程

## 输入来源

读取仓库根目录下的 `.ai-review-report.json`，将其作为修复清单。**仅处理 `userType` 为 `"yes"` 的问题**，`"no"` 视为误报不修复。报告中包含：
- `files[].path` 文件路径
- `files[].issues[].line` 问题行号
- `files[].issues[].message` 问题原因
- `files[].issues[].suggestion` 修复建议

`.ai-review-report.json` 在 Repair 模式中只允许读取，不允许作为修复对象被修改、删除、清空、覆盖或通过调整其内容来规避问题。

## 修复要求

1. 根据报告逐条定位问题并修复。
2. 修复时以最小改动为原则，避免破坏既有逻辑。
3. 修复完成后，确保问题不再触发（如需运行测试但无法执行，需明确说明原因）。
4. 只能修改实际存在问题的源代码、配置或测试；禁止通过编辑 `.ai-review-report.json` 让问题“消失”。
5. 若某条问题无法安全修复，保留报告原状，并在输出清单中说明未修复原因与下一步建议。

## 输出要求

修复完成后必须输出清单，包含：
- 已修复的问题（文件路径 + 问题描述）。
- 未修复的问题（原因 + 下一步建议）。

## 原则

- 优先保证功能正确性与安全性，不做猜测性大改。
- 避免引入新问题或破坏既有逻辑。
- 报告文件是修复输入，不是修复目标。
